     126              : ## Namespaces
     127              : 
     128              : CEX namespaces group functions under one global name, reducing C name collisions and keeping
     129              : project structure navigable. They also add OOP-ish behavior to structs.
     130              : 
     131              : ### Key features
     132              : 
     133              : * generated from the `.c` file — no `.h` upkeep on signature changes
     134              : * `.c`/`.h` filename must match the namespace name
     135              : * only the namespace name is exposed globally (smaller collision surface)
     136              : * sub-namespaces give a decision tree in LSP completion
     137              : * `.` separator reads better and highlights namespace vs function
     138              : 
     139              : ### In a nutshell
     140              : 
     141              : A namespace is a global `const` struct of function pointers:
     142              : 
     143              : ```c
     144              : #define CEX_NAMESPACE __attribute__((visibility("hidden"))) extern const
     145              : 
     146              : struct __cex_namespace__KeyMap {
     147              :     Exception (*create)(KeyMap_c* self, char* input_dev_or_name);
     148              :     void      (*destroy)(KeyMap_c* self);
     149              :     Exception (*handle_events)(KeyMap_c* self);
     150              : };
     151              : 
     152              : CEX_NAMESPACE struct __cex_namespace__KeyMap KeyMap;
     153              : ```
     154              : 
     155              : Usage:
     156              : 
     157              : ```c
     158              : KeyMap_c keymap = { 0 };
     159              : e$goto(KeyMap.create(&keymap, file), end);
     160              : e$goto(KeyMap.handle_events(&keymap), end);
     161              : ```
     162              : 
     163              : `_c` on the struct hints it has a code namespace (a class/object); `_s` means plain data.
     164              : 
     165              : ### Sub-namespaces
     166              : 
     167              : One extra level groups large namespaces, e.g. `str.slice.*` for `str_s` operations,
     168              : `str.convert.*` for conversions, and `str.find()` at the root. They let you type the
     169              : function name as a decision tree (`str` → `slice` → function).
     170              : 
     171              : ### How to make a namespace
     172              : 
     173              : 1. create `src/foo.c` and `src/foo.h`
     174              : 2. write `foo_fun1()`, `foo_fun2()`, `foo__bar__fun3()` — they become `foo.fun1()`,
     175              :    `foo.fun2()`, `foo.bar.fun3()`
     176              : 3. run `./cex process src/foo.c`
     177              : 
     178              : Caveats:
     179              : 
     180              : * `.c` and `.h` must share the folder and the `foo` prefix
     181              : * namespaced functions start with `foo_`; sub-namespace uses `foo__subname__`
     182              : * only one level of sub-namespace is allowed
     183              : * signatures need not be declared in the header — `.c` statics are enough
     184              : * `static inline` functions are excluded
     185              : * `foo__some` is treated as internal and excluded
     186              : * use the exact `src/foo.c` argument to create a namespace; `all` only updates existing ones
     187              : * the parser also accepts `cex_foo_fun1()` and strips the `cex_` prefix when building names
     188              : 
     189              : CLI:
     190              : 
     191              : ```sh
     192              : ./cex process src/foo.c   # create or update one namespace
     193              : ./cex process all         # update all after signature changes
     194              : ```
     195              : 
     196              : Note: function-pointer calls may be slower without optimization; `-O1` turns them into direct
     197              : calls. For shared libraries, prefer plain C functions.
     198              : 
     199              : ## Agentic workflow
